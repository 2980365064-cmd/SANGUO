# 《汉祚再兴・刘备传》核心玩法与界面架构设计

> 状态：讨论定稿 v1。本文定义产品体验、玩法边界、信息架构与阶段目标；接口、数据库迁移与代码任务在后续实施文档中单列。

## 1. 定位与设计原则

《汉祚再兴・刘备传》是从建安十三年（208）赤壁前夕开始、仅以刘备视角游玩的 AI 对话式三国政略模拟器。

玩家的主要体验不是在地图上拖军队或在数值表中刷效率，而是：面对局势，问人、识人、作出取舍、颁布方略，并承受天下对这些取舍的反馈。地图、人物数值、资源、战役、外交和历史事件均为这条体验链提供事实、代价与叙事材料。

必须遵守的原则：

- **局势优先于功能入口。** 每回合先让玩家知道“现在最要紧的是什么”，再进入廷议、密谈或方略筹备。
- **颁令是唯一提交点。** 地图、城池、廷议、密谈及任何面板都只能提出、编辑或审阅草案；只有颁令才能将本月行动提交结算。
- **硬规则决定事实，AI 解释事实。** AI 可以判断、提出、叙事、在许可范围内选择战术；不得用文本直接改变死亡、领土、兵力、条约、资源或结局。
- **刘备的仁义必须有后果。** “天下口碑”既是规则变量，也是士人、百姓、盟友、降将与敌手的多声部反馈，不能只是文案。
- **公开方略与密令分层。** 前者可被军府、地方和盟友知悉；后者必须具有授权、知情范围、行动边界、风险与回奏。
- **历史语境优先。** 208 开局不采用“州牧”或“圣旨”。地图、文书、官职和制度称谓随刘备身份发展而变化。

## 2. 回合总循环

```text
每月总计（上月回奏）
  → 本月局势与行动枢纽
  → 府堂廷议 / 单独密谈 / 地图与人物查阅
  → 建议与方略草案入簿
  → 审阅与颁令
  → 分阶段流式推演（必要时暂停裁断）
  → 每月总计
```

上图只描述**状态发生的先后关系**，不是一次性、不可回头的页面向导。本回合内玩家可通过固定入口随时重开“每月总计”和“本月局势与行动枢纽”：前者用于回看已完成阶段、上月回奏和历史条目，后者用于回到当前问题、地图态势与方略簿。只有推演进行中或待决检查点未处理时，才按状态限制会造成事实冲突的操作；不限制查阅。

### 2.1 本月局势与行动枢纽

它是游戏中的默认工作场景，叠加在地图态势背景之上，而不是另一个传统管理面板。

- 主区按紧急、重要、机遇、建议展示本月问题：战线压力、外交窗口、地方困境、人物争议、历史压力和待续方略。
- 每一条局势给出可理解的因果摘要，并提供最合适的行动入口，例如“府堂廷议”“召见人物”“查看城池”“拟入草案”。
- 右侧固定显示“本月军府方略簿”：只显示草案标题、类别、承办人、风险、校验状态与数量。它让玩家随时知道自己正在筹备什么。
- 地图保持态势与情报用途：查看城池、军队、战线、补给和地形，并将对象带入草案；不承担直接改变世界的操作。

### 2.2 问策、密谈与建议

廷议用于大方略分歧，密谈用于试探、安抚、追问、秘密授权和人物关系。二者都不是“点一下得到最优答案”的按钮。

- 每位发言者至少说明形势判断、建议、收益、风险、仁义影响、执行条件与个人立场。
- 对话结论可以生成建议或方略草案，但不得立即生效。
- 建议保留来源（廷议、密谈、事件、人物拟令）、提出者、分类、紧急度、原文、风险与状态；可采纳、编辑、搁置或本月恢复已丢弃条目。
- 密谈产生的密令草案同样要进入本月方略簿，但默认不展开正文。

### 2.3 审阅与颁令

点击方略簿后进入独立的“审阅与颁令”场景，而不是在地图侧栏完成复杂编辑。

- 左侧是本月草案清单：内政、军事、外交、其他，以及独立的密令层。
- 右侧逐条编辑“结构化行动 + 文书说明”。结构化字段是规则唯一输入；白话说明承载意图；AI 润色生成的正式文书只用于展示和史册。
- 页面持续显示每条校验结果。所有可提交草案通过后，玩家一次性颁令；未通过的草案必须明确指出对象、资源、权限、冲突或字段问题。
- 颁令生成不可变的本月行动快照，并建立自动存档与审计起点。

### 2.4 月度推演、裁断与回奏

月度执行按阶段进行：

1. 内政与人事；
2. 军令、战役与补给；
3. 外交与盟约；
4. 密令、事件与暗流；
5. 天下变化、口碑与资源结算。

每个阶段先完成规则结算，再生成可追溯的流式叙事。重大待决事件采用**阶段检查点**：已完成阶段的事实、审计、文本与自动存档已落账；推演暂停，玩家裁断后从下一阶段续推，绝不重放或改写已结算结果。

执行完成后首次进入完整的“每月总计”回合交接场景。玩家确认阅毕后进入下月局势；这只是完成首次交接，不会关闭“每月总计”入口，玩家仍可随时回看当前或过往回奏。

## 3. 方略、指令与文书体系

### 3.1 唯一行动合同

所有会影响世界的内容都使用同一生命周期：

```text
建议 / 手动起草 → 草案 → 校验通过 → 已颁 → 执行中 / 已完成 / 部分成功 / 失败 / 已撤回
```

这份行动合同既服务公开方略，也服务密令和跨月任务。任何单独的“立即任命”“立即调防”“聊天即结盟”均不允许绕过它。

### 3.2 分类与编辑规则

公开方略分为四类：

- **内政**：任免、屯田、治水、税赋、治安、安抚、征募、训练、工程。
- **军事**：持续战役、调防、守备、补给、整编、犒赏、撤军。
- **外交**：遣使、停战、结盟、通商、劝降、求援、会盟申请。
- **其他**：寻贤、宗族、封赏与不属于前三类的公开事务。

密令独立成层，不归入“其他”。它至少包含执行者、目标、授权边界、知情范围、期限、暴露风险和回奏条件；提交总览中只显示风险等级与边界校验状态。

每条草案都由两部分组成：

1. **结构化行动**：对象、执行者、目标、投入、优先级、期限、边界等可校验字段；
2. **文书说明**：玩家或臣将对意图、方法、取舍与限制的自然语言说明。

### 3.3 身份与文书语境

系统主名称始终为“军府方略”，保证规则、史册与界面不会因身份改变而换轨；正式文书的抬头随身份变化：

| 时段 | 系统展示 | 正式文书抬头 |
| --- | --- | --- |
| 208 至 219 年称汉中王前 | 左将军府方略 | 左将军府令 |
| 219 至 221 年称帝前 | 汉中王府方略 | 汉中王令 |
| 221 年称帝后 | 朝廷方略 | 诏令 |

润色严格保持结构化行动的语义，不得借文辞增删目标、资源、许诺或后果；可恢复为白话原文，也可多次生成不同措辞。

## 4. 核心玩法系统

### 4.1 内政与地方治理

中央幕府负责廷议、拟令、督办与全势力效率。地方采用“**治理单元主官 + 按需属官**”，而非为每个战略节点强制填满四人。

- 默认岗位是郡守/县令等地方主官；治理规模、治安压力和方略需求达到条件后，才需要县尉、功曹、主簿等属官。
- 空缺由曹署代办，但产生明确效率损失，不阻塞回合。
- 主官、属官、中央督办与地区状态共同影响粮食、财政、治安、民心、流民、吏治和方略传达；人物适配度、清廉、地方士族态度与监察同样进入结算。
- 任免只能创建草案。破格提拔、任用本地士族、无故罢免等政治后果进入忠诚、士族支持、民心与口碑反馈。

### 4.2 军事：目标式持续战役

不提供前台路线拖拽和手动逐格行军。玩家下达持续战役方略时指定主将、副将（可选）、可投入兵力与兵种、战略目标、目标地点与边界。

- 一项战役可以跨月存在，具有筹备、行军、接战、围城、收尾、撤回等阶段；玩家每月可续行、增援、调整目标或撤回。
- 后台仍保留地区邻接、地形、关隘、江河、补给距离等事实校验。它们决定可达性、耗时和风险，不再以路线网络作为前台玩法。
- 战役胜负、伤亡、城池归属、将领生死/伤俘、缴获和士气由规则层决定。AI 只能在白名单战术与规则上下限内选择叙事性处理，并生成“行军 → 接战 → 决战 → 收尾”的回奏。
- 调防、征募、训练、整编和补给同样是方略，不再是军队面板中的即时操作。

### 4.3 外交：使臣先行，会盟后置

常规外交以使臣为核心。玩家指定使者、对象、目的与条款边界，月度推演基于能力、关系、互信、实力、历史压力与对方性格给出回书和结构化结果。

君主会盟属于高阶外交，不是随时可开的聊天：需要地缘、使臣铺垫、共同利益、关系或历史事件等前提。会盟时允许自由对话，但联盟、领土交换、联姻、联合出兵等一律先形成结构化条款草案，经规则校验与双方确认后才生效；对话文本本身不能改写世界。

### 4.4 天下口碑与军政资源

六项军政资源维持为：军资、粮秣、民望、名分、军心、士族支持。它们有明确的收支、上限、风险与指令关联。

另设第七项慢变量：**天下口碑**。

- 口碑反映刘备“仁义”的长期可审计结果，不是普通消耗品。
- 守约、护民、让利、宽待降人、救援盟友等可累积口碑；背盟、杀降、弃民、滥征、失信等会损害口碑。
- 它影响人才投效、民众归附、地方合作、盟友信任、降将态度、事件分支与结局评语。
- 玩家看到的是称号、趋势与群体反应；规则层保存数值与来源，月报说明变化原因。

### 4.5 人物、派系与历史压力

人物能力、特质、忠诚、关系、已知情报与派系影响问策、执行和回奏。派系应服务具体冲突，不能变成额外的表格管理；元老、荆州、益州等政治群体在相应历史阶段逐步进入，而不是开局一次性堆满。

固定历史事件提供压力、窗口和人物关系变化，而非强制复刻。随机事件制造局部变数；两者都必须通过规则判断是否触发、改写、替代或失效，并可生成建议或待决事项。

## 5. UI 信息架构与视觉原则

### 5.1 场景分工

| 场景 | 唯一职责 | 不承担的职责 |
| --- | --- | --- |
| 本月局势与行动枢纽 | 提出问题、引导问策、展示方略簿 | 完整编辑和直接结算 |
| 府堂廷议 | 多人公开争论与建议沉淀 | 直接颁令 |
| 私下密谈 | 人物关系、情报、秘密方案 | 直接改写世界 |
| 审阅与颁令 | 编辑、润色、校验、统一提交 | 地图浏览与长篇回奏 |
| 流式推演 | 展示阶段执行与暂停裁断 | 修改已结算阶段 |
| 每月总计 | 核销、回奏、首次回合交接、历史回看入口 | 继续编辑本月草案 |
| 地图与城池详情 | 态势、情报、对象选择 | 独立管理循环 |

### 5.2 信息密度与表现形式

- 保持宣纸、木案、墨迹、竹简、朱印等历史材质；不要用现代后台卡片、大片纯色遮罩或空洞留白覆盖原始地图。
- 主界面仅长期展示关键资源、天下口碑趋势、最重要的局势和方略簿状态。细节数值通过地图详情、人物发言、战报、回书与月报展开。
- 方略校验使用明确文字与图标说明“可提交 / 待补字段 / 资源不足 / 权限冲突 / 执行者冲突”，不能只用颜色或笼统错误提示。
- 月报中的规则审计与叙事分层：先给可读结论，再允许玩家展开伤亡、补给、地形、随机值、计策和资源变动；禁止把原始 JSON 直接作为玩家界面。
- 移动端可把固定方略簿收为底部抽屉；桌面端采用右侧固定簿，保证局势和筹备状态同时可见。

## 6. AI 与规则边界

### 6.1 规则层的最终权力

规则层验证目标合法性、资源、权限、人物与军队状态、同一执行者冲突、地缘可达性、外交条约、战役结算、重大人物状态、领土和结局。AI 调用失败时，规则层仍应完成可恢复的纯规则结算，并以简洁模板回奏。

### 6.2 AI 的许可范围

AI 可以：

- 根据已确认事实生成廷议分歧、密谈反应、建议、文书润色、使臣回书、战役叙事与天下舆论；
- 在许可的战术、外交或事件裁量范围内给出建议和有限修正；
- 将越权、高风险或不完整提议标为待审计/待裁断，而不是自动应用。

AI 不可以：生成或确认死亡、领土变更、凭空援军、兵力/资源突变、条约生效、结局改写等重大事实。

## 7. 阶段路线图

### P0：单一闭环的可玩垂直切片

交付“局势 → 问策 → 草案 → 审阅颁令 → 分阶段推演 → 每月总计”的完整循环。

- 行动枢纽、固定方略簿、建议入簿、完整审阅与颁令页。
- 内政、军事、外交、其他四类结构化方略及独立密令层。
- 一条持续战役、一类使臣外交、基础内政、中央任免。
- 前后双层校验、阶段检查点 HITL、自动存档、可展开的月度总计。
- 地图保留态势与对象选择；不再显示前台路线网络。

### P1：三大系统的纵深

- 治理单元主官与按需属官、治理效应与人才流转。
- 战役规则包、结构化战报、调防/训练/整编/补给。
- 更完整的使臣外交与受条件约束的君主会盟。
- 基础历史事件框架、存档管理与历史回看。

### P2：长期叙事与体验打磨

- 派系、忠诚、身份成长、胜败结局、随机事件扩充。
- 文书化回奏、术语说明、新手引导、设置与无障碍选项。
- 天下口碑的多群体反馈、长期关系与史评。

### 暂缓项目

科技/国策树、剧本编辑器、多势力可玩、细粒度建筑管理。它们在主循环稳定前不得重新成为主入口。

## 8. 验收标准

- 玩家能在不打开传统管理面板的情况下完成一整月的主要决策。
- 本月局势与行动枢纽、每月总计均可在非推演锁定状态下反复进入；首次交接确认不会使它们消失。
- 任何影响世界的操作都能在方略簿、颁令快照、月度回奏和历史记录中追溯到同一条方略。
- 对话、地图、任免、调防、外交均不能绕过颁令直接改变世界。
- AI 失效时，回合仍可安全结算；AI 越权提议不会写入事实。
- 阶段暂停后能够继续推演，已完成阶段不重复执行、不被重算。
- 玩家能理解一条方略为何成功、部分成功、失败或延续中，并能展开查看规则依据。
- 地图和数值服务人物、局势与裁断；正式文书和 UI 术语符合 208 年起刘备身份演进。
