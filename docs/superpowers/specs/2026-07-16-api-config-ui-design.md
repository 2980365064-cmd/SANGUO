# 主界面 API 与模型配置入口设计

## 目标

在“汉祚再兴 · 刘备传”的标题主菜单和游戏内侧栏各增加一个“API 配置”入口，共用同一个国风配置弹窗。沿用明末版已经存在的 LLM 配置、连通性校验和持久化能力，不新增第二套配置存储。

## 范围

本次包含：

- 标题主菜单的“API 配置”按钮。
- 游戏内侧栏的配置按钮。
- 可复用的 API 配置弹窗。
- 当前配置摘要、密钥占位状态、保存中状态、成功及错误反馈。
- 菜单态与游戏态分别调用现有后端接口。
- 前端合同测试、TypeScript 构建和实际服务验证。

本次不包含：

- 自动获取服务商模型列表。
- 同时保存多套提供商预设。
- 修改现有 `runtime_llm.json` 格式。
- 改写后端模型调用架构。

## 交互设计

### 入口

标题主菜单在“新启史卷”和“续读旧策”下方增加次级“API 配置”按钮。无 API Key 时，原提示改为“尚未配置大模型，请先完成 API 配置”，按钮仍保持可用。

游戏内侧栏在六个业务入口和“月末推演”之外增加独立配置按钮。它不属于朝议、军令等业务面板，点击后只打开弹窗，不切换当前面板。

### 弹窗

弹窗使用现有宣纸、赭石、朱红和印章按钮语言。打开时读取调用方已经取得的配置摘要；游戏内若需要最新值，则调用现有配置读取接口刷新。

首次没有已存配置时，基础字段使用后端一致的默认值：Base URL 为 `https://api.openai.com/v1`，模型为 `gpt-4o-mini`；API Key 保持空白。

默认展开“基础配置”：

- API Base URL
- 模型名称
- API Key

“高级配置”默认折叠，包含：

- 最大 Token
- 总超时、连接超时、读取超时
- 思考等级
- 高级模型名称
- 高级模型 Base URL
- 高级模型 API Key
- 高级模型思考等级

密钥永不从后端回显。已有密钥时显示“已配置，留空则继续使用”；用户输入的新密钥只保存在组件状态中，关闭弹窗即丢弃未保存内容。

### 保存流程

点击“测试并保存”后：

1. 前端校验 Base URL 和模型名称非空，数值字段为正数。
2. 按所在页面调用对应接口。
3. 按钮进入“正在测试连通性”状态，表单和关闭外点击暂时禁用，避免重复提交。
4. 后端依次验证主模型及已启用的高级模型；全部通过后才写入 `runtime_llm.json`。
5. 成功后更新前端配置摘要和“已配置”状态，展示成功消息；用户可关闭弹窗继续当前流程。
6. 失败时不覆盖旧配置，弹窗保留输入，并显示后端返回的服务商错误。

## 组件与接口

新增可复用组件 `ApiConfigModal`，只负责表单、折叠区、提交状态和错误展示。它通过 props 接收：

- 当前 LLM 配置摘要
- 菜单态或游戏态
- 关闭回调
- 保存成功回调

前端类型新增完整的 `LlmConfigSummary`，并让 `MenuStatus` 包含后端已经返回的 `llm` 字段。

前端 API 层新增：

- `saveMenuLlmConfig(payload)` → `POST /api/menu/llm`
- `getGameLlmConfig()` → `GET /api/llm/config`
- `saveGameLlmConfig(payload)` → `POST /api/llm/config`

菜单态使用 `/api/menu/llm`，它不依赖已经创建的游戏会话。游戏态使用 `/api/llm/config`，保存后即时替换当前 `GameSession` 的模型配置，无需退回主菜单。

两类接口保持现有语义：API Key 留空时复用已保存密钥；高级 API Key 留空时复用已保存的高级密钥。游戏态提交时，如果摘要表明已有高级密钥而输入框为空，前端将该字段转换为后端约定的 `__keep__`，避免游戏内接口把旧高级密钥清空；菜单态直接留空，由现有菜单接口复用旧值。前端不自行持久化密钥。

## 错误处理与安全边界

- 配置保存必须由后端真实连通性测试通过，前端不得只凭 HTTP 请求已发出就显示成功。
- 后端返回的结构化 `message`、`provider_message` 和状态码由现有 `ApiRequestError` 转换为用户可读信息。
- 任何响应都只包含 `has_api_key` / `has_advanced_api_key`，不包含密钥明文。
- 保存失败不关闭弹窗、不清空用户输入，也不替换当前生效配置。
- 游戏内保存成功只更新模型配置，不重置盘面、对话、回合或存档。

## 测试与验收

按 TDD 实施：先写前端静态合同测试并确认因缺少入口、组件和 API 方法而失败，再做最小实现。

验收条件：

- 标题主菜单和游戏内侧栏都能打开同一个配置弹窗。
- 基础和高级字段能从当前摘要初始化。
- 已配置密钥不会回显，留空保存能沿用旧密钥。
- 保存期间不可重复提交。
- 菜单态使用 `/api/menu/llm`；游戏态使用 `/api/llm/config`。
- 成功与后端连通性错误均在弹窗内明确显示。
- `python3 -m pytest tests -q` 无失败。
- `web/` 下 `npm run build` 成功。
- 重新构建后，正在运行的 FastAPI 首页可加载新产物，两个入口可见。

## 不变约束

- 不初始化 Git 仓库。
- 不改变三国硬规则、存档场景 id 或玩家可见业务合同。
- 不把密钥写入浏览器本地存储、URL、日志或响应正文。
