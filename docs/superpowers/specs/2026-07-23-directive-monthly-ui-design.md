# 方略簿与月度史册 UI 迁移设计

## 目标与范围

本批次完成核心闭环中“军府方略”和“每月总计”的视觉迁移。二者继续作为常驻地图上的有限宽度浅纸内容卷，不改变任何 API、草案状态机、月结接口或世界事实。生成的 UI 资产只从既有令牌引用，绝不修改图像文件。

## 方案

采用增量迁移：保留现有数据读取、草案编辑器和颁令/进入下月行为；用既有 `AppFrame`、`PaperPanel`、`SectionHeading`、`StatusMark`、`ActionSealButton` 和 `GameDialog` 替换页面私有的标题栏、白卡、状态彩色字与浏览器确认框。页面样式写入 `styles/scenes/directive.css` 与 `styles/scenes/monthly-report.css`，不在 TSX 内保留 `<style>`，也不删除仍由其他页面依赖的旧规则。

## 页面契约

### 军府方略

- 顶部为场景标题、返回和唯一主行动“审阅与颁令”。
- 主体保持“拟定—审阅—下达”可见步骤；左列是筛选、总览、模板与草案清单，中列是已选草案正文，右列显示执行上下文/风险。
- 草案状态统一映射为 `StatusMark`：待校验=action，已校验/已颁令=complete，已拒绝/无效=danger。
- 删除以 `GameDialog` 确认；已颁令草案不可删除。
- 空、加载、错误和无选中草案均给出文字说明与下一步操作。

### 每月总计

- 顶部为“本月结论”；中部按“已发生之事”组织批次、月报和人物/口碑；底部为“天下余波与下月待议”。
- 执行结果使用时间线/列表与 `StatusMark`，不保留内联色值、仪表盘式大数字或普通白色卡片。
- 重大天下反应保持既有裁断 API 与阻断下月语义；月结确认是唯一朱砂主行动，清楚说明不可逆后果。
- 加载、错误、无批次和无月报均由同一内容卷呈现；错误提供重试，不刷新整个页面。

## 样式与可访问性

- 使用现有浅宣纸、淡墨、灰青和朱砂令牌；不引入深棕大底、金边或通用后台卡片。
- 1024×768 起允许内容卷自身滚动，底部行动不被导航遮挡；1440×900 是基线截图尺寸。
- 对话框保持 Esc、焦点陷阱和可见关闭方式；按钮包含可读文本，状态不只依赖颜色。
- 动效只取现有 120–240ms 令牌并服从减少动效设置。

## 非目标与数据边界

- 不新增随机域、数据表、世界行动、AI 提案或月度结算步骤。
- 不改变草案/批次 API 的请求和返回合同；UI 只读取现有数据并发起既有编辑、删除、裁断和下月请求。
- 不处理其余核心页面、全量 CSS 兼容层移除或不可达存档状态；这些留在后续批次。

## 验收

1. 前端构建及现有契约测试通过。
2. 新增/更新契约测试覆盖两个页面的组件层级、唯一主行动及不再含内联样式/浏览器确认框的约束。
3. 有活存档时在 1440×900 和 1024×768 截图；检查长文本、空态、加载/错误、浮层、地图层级和主要点击区域。
4. 审查变更，确认没有修改 AI 活世界规则或生成资产。
